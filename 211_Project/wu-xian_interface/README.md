# CMT2119B 底层驱动移植说明

## 当前完成范围

本目录是 GD32E230C8T6 的发送端底层驱动，已加入本工程 Keil 的 `wu-xian_interface` 分组和头文件搜索路径。

只连接四根通信线：

| 无线芯片信号 | MCU 引脚 |
| --- | --- |
| CSB | PA4 |
| FCSB | PB0 |
| SCLK | PA5 |
| SDIO（双向数据） | PA7 |

无线芯片 GPIO1、GPIO2、GPIO3 不连接，也不为它们初始化任何 MCU 引脚。使用软件 SPI，因此只启用 GPIOA/GPIOB 时钟，不启用硬件 SPI 外设。

当前 `User/main.c` 保持原有串口演示；驱动参与编译，但尚未在主循环中调用。当前生成的 HEX 也仍是串口演示，不是无线收发固件。

## 源码来源及改动

源自本地 `资料/CMT2119B及CMT2219B芯片手册在这/GPT整理的/CMT2119B官方驱动资料/CMT2300A_Demo_STM32_V1.0.1/CMT2300A_Demo(STM32)V1.0.1/CMT2300A_Demo_Tx/USER`。

- `cmt2300a.c/h`、`cmt2300a_defs.h`：厂家驱动及寄存器定义，保留原名和版权，便于对照资料。只使用 CMT2119B 支持的公共及发送功能，不代表该芯片拥有 CMT2300A 的全部功能。
- `cmt2300a_hal.c/h`：厂家硬件抽象层，移除未接线 GPIO 的操作；新增 `CMT2300A_ReadPollingFlags()`，通过 SPI 读取标志并处理标志极性。
- `cmt_spi3.c/h`：保留厂家的寄存器/FIFO 访问时序，替换 MCU 操作和空循环延时。
- `cmt_port.c/h`：项目自定义 GD32 适配层，使用 GD32 官方 GPIO/时钟函数和现有 `delay_1us()`、`delay_1ms()`。
- `cmt2119b.c/h`：项目自定义芯片入口及查询接口。
- `typedefs.h`：固定宽度类型，去掉 STM32 依赖，以及原示例容易污染其他代码的 `data`、`code` 等宏。

原驱动依赖持续递增的中断计时变量；本工程 SysTick 用作阻塞延时，不提供该变量。因此状态切换改为最多 100 次查询，每次先延时 100 微秒，再加 SPI 访问耗时。不是精确的 10 毫秒墙钟超时。无响应时返回 FALSE，不会无限等待。非法状态命令直接返回 FALSE。

## 初始化顺序

1. 先调用工程现有的 `systick_config()`，再调用 `CMT2119B_Init()`。
2. Init 内部开启 GPIOA/GPIOB 时钟，设置空闲电平和四线方向，执行软复位、状态初始化和寄存器读写检查；成功后停在 STBY。
3. 返回 TRUE 仅说明初始化和寄存器访问检查成功，不代表已配置好射频或识别了芯片具体型号。
4. 后续加载 **RFPDK 选择 CMT2119B 导出的参数表**，再调用 `CMT2119B_ConfigPolling()`，然后依据最终包格式启动发送。

当前仅 SPI 初始化/访问检查示例（不是完整无线收发程序）：

```c
#include "systick.h"
#include "cmt2119b.h"

/* 在原工程初始化阶段调用 */
systick_config();
if (!CMT2119B_Init()) {
    /* 检查供电、接线和 SPI 通信；不要继续启动无线操作。 */
}
```

Init 和底层读写均为阻塞调用；不要在中断中调用，也不要在多处并发使用，因为 SDIO 和现有 SysTick 延时资源会被共享。初始化完成后软件 SPI 会释放 SDIO 为输入，CSB/FCSB 为高，SCLK 为低。

## 不依赖 GPIO 的状态查询

`CMT2119B_TxDone()`：读取 TX_DONE 标志，不会清除标志。

标志查询由 SPI 完成。厂家 `CMT2300A_ClearInterruptFlags()` 用于显式清除标志；先处理数据/结果，再按收发流程清除，避免丢失事件。接收端还须及时处理错误和溢出，清理 FIFO 后重新进入 RX。

寄存器读写、FIFO 读写、SLEEP/STBY 和支持方向的状态切换，继续调用厂家 `CMT2300A_*` 接口。FIFO 接口直接传输原始字节，暂未确定定长/变长协议；后续须检查缓冲区容量、长度字段和硬件 FIFO 容量，不能直接套用旧示例读取外部包长的写法。

## RFPDK 参数单独处理

本次没有复制 CMT2300A 的 `cmt2300a_params.h`，也没有添加空参数或冒用 2119B/2219B 的配置。本次亦不确定频率、速率、CRC、包长、设备 ID 或频道方案。

后续通过厂家 `CMT2300A_ConfigRegBank()` 加载 CMT2119B 对应的各寄存器区。参数加载后，按厂家要求进入 SLEEP 使配置生效，再回到 STBY 并配置轮询；最终流程结合导出的配置核对。频率/包格式配套后才能进行实物收发测试。
