# 无线配对与按键 Demo V2

本版已替代之前的持续发序号 Demo。当前只通过串口显示 RUN/STOP，不驱动执行器。
所有应用函数位于各自 wu-xian-App/wireless_demo.c。底层 wu-xian_interface、原始 .exp、User/main.c、Keil工程配置未被本次修改。

## 打开和烧录

使用原工程：`211_Project/Project/GD32E230C8T6.uvprojx`、`221_Project/Project/GD32E230C8T6.uvprojx`。
现有主程序已调用下面两个自定义函数，不必再次替换：

```c
#include "wireless_demo.h"
int main(void)
{
    WirelessDemo_Init();
    while (1) WirelessDemo_Process();
}
```

两块板都需要烧录本版。V1 的四字节纯序号包与 V2 控制包不兼容。
串口保持 115200、8N1，ASCII文本发送，每条命令末尾必须带回车或换行（CR、LF、CRLF均可）。不要勾选十六进制发送。
首次烧录或恢复默认后 PAIRED=0，停止参与控制；必须分别配置两端。

## 串口命令

| 命令 | 作用 |
| --- | --- |
| `GET` | 查询编号、频道、实际频率、配对、存储、无线状态和日志丢弃计数 |
| `SET,1,0` | 设置 ID=1、CH=0，保存到 Flash 并立即应用 |
| `SET,2,1` | 设置 ID=2、CH=1，供另一对设备使用 |
| `DEFAULT` | 保存默认 ID=1、CH=0、PAIRED=0，停止参与控制，等待重新 SET |
| `HELP` | 打印命令格式 |

ID 为十进制 1..4294967295，CH 为0..5。不接受负数、溢出、额外字符或空参数。每次发送一条，等待回复后再发下一条。
同一对两端必须设置相同 ID 和 CH；不同对必须分配不同 ID。编号无需重编译程序，不通过无线配置。
`OK SAVED APPLIED` 表示保存并应用成功。`ERR APPLY saved` 表示参数已保存但无线初始化失败，会自动重试，不能视为链路已经可用。
没有锁定命令，串口始终可以查询、修改、恢复默认。普通断电保留设置；整片擦除会清除设置。

例如第一对的 COM2 和 COM18 都发送 `SET,1,0`。第二对两端发送 `SET,2,1`。
工厂可按 CH=(编号-1)%6 分配初始频道；这是分散负载的起点，需结合现场分布调整。同一频道上的不同 ID 仍然会互相干扰。

## 成对参数

| 参数 | 211发送端 | 221接收端 |
| --- | --- | --- |
| 基础频率 | 433.920MHz | 同左 |
| 频道0/1/2/3/4/5 | 433.920 / 434.070 / 434.220 / 434.370 / 434.520 / 434.670MHz | 同左 |
| 频道步进寄存器 | 60，即150kHz | 同左 |
| 配对编号 | 串口设置的32位Node ID | 仅接受对应ID，并由应用再次检查 |
| 调制/速率/FSK频偏 | GFSK / 9.6kbps / 10kHz | 同左 |
| 无线芯片晶振设计容差 | 26MHz，40ppm | 26MHz，40ppm |
| 发射功率导出值 | +13dBm | 不适用 |
| AFC_OVF_TH(0x27) | 不适用 | 21(0x15)，六个频道相同 |
| 前导码 | 8字节0xAA | 检测2字节0xAA |
| 同步字 | 0x2DD4A7B3 | 同左 |
| Payload | Node ID 4字节 + DATA 4字节，不含CRC | 同左 |
| CRC | CCITT-16，初值0xFFFF，整个Payload | 同左 |

频道偏移指移动载波中心频率，不改变GFSK的10kHz调制频偏。所有频道在同一个芯片频率分段内。
AFC阈值根据本地AN1971表公式、两端各40ppm及上述频率范围重算；原导出0x27=10由应用覆盖为21。`.exp`和96字节参数数组保持原样。
本方案不等于100对同时通信保证。可以分配100对唯一编号，但同频道同时发包可能碰撞，邻频道还受实际滤波、功率和距离影响。
频率与功率是软件测试设置，不代表已验证工业升降产品的无线电合规；正式产品需结合具体设备类别、天线和实测辐射功率核定。

## 按键和时序

发送板公共脚接GND，PA9/PA10外接上拉；初始化先启用GPIOA时钟，再配置两个输入及内部上拉。
任一输入低电平均视为按住。一级变二级、二级退一级保持RUN；只有全部释放才变STOP。
合并后的按键状态需要连续稳定10ms才改变，对按下和完全松开两个边沿分别消抖，不使用阻塞延时。

- 按住：持续发RUN，发包开始之间间隔随机40..60ms。
- 松开：优先停止旧状态发送，重复发送3个STOP，开始间隔随机25..35ms，之后不再占用空口。
- 接收：有效RUN立即更新状态；有效STOP立即停止。
- 接收端最后一个有效控制包后85ms没有更新，切换STOP并输出 `EVENT STOP TIMEOUT`。错误ID、CRC错误和无效协议包不续期。
- 无线故障或本地改配置时立即将本地状态置为STOP。配置更改属于维护操作，期间会中断控制。

85ms是给主循环和串口传输留余量的超时阈值，用于100ms响应目标。按键到接收、松开到停止的实板时间仍需测量；干扰下RUN包也会丢失，因此可能出现按住但接收端超时停止，再次收到有效RUN后恢复。
随机间隔用于减轻持续碰撞；211只有发送能力，不具备监听空闲信道或无线ACK的能力。持续干扰时无法保证命令100ms必达。

## 数据和日志

8字节空中Payload：`ID[31:24] ID[23:16] ID[15:8] ID[7:0] A1 ACTION SEQ_H SEQ_L`。
ACTION=01表示RUN，00表示STOP。16位序号每次本地TX_DONE后增加，到65535后回绕。
TX FIFO只写后4字节，Node ID由硬件插入；RX FIFO读完整8字节。这保留了之前实板验证过的FIFO不对称行为。
序号只用于观察通信，不是防重放认证或可靠交付确认。

```text
BUTTON DOWN
EVENT RUN PACKET
RX seq=12 cmd=RUN state=RUN data=00 00 00 01 A1 01 00 0C total=12 new=6 err=0
BUTTON UP
EVENT STOP PACKET
EVENT STOP TIMEOUT
```

BUTTON是发送端识别到的消抖按键事件；EVENT是接收端状态变化，PACKET表示收到命令，TIMEOUT表示断流停止。
每300ms打印统计，cmd表示最近包内容，state表示当前状态；即使最近包是RUN，超时后state也会显示STOP。
正常松开后没有新包属于正常，显示IDLE。total/new是成功发送或有效接收包数，err不是丢包数，err=0不代表零丢包。
LOGDROP为本地日志队列满时丢弃的整条日志数，不是无线丢包数。
USART1接收/发送均由应用中断缓存，日志不会等待整行发送完成；不要再添加另一个USART1_IRQHandler，也不要在主循环加300ms延时。

## Flash与资源

使用现有BSP初始化SysTick、USART1(PA2/PA3)，独占TIMER2作为10kHz计时；发送端额外占用PA9、PA10。
设置保存到MCU最后两页：0x0800F800..0x0800FBFF、0x0800FC00..0x0800FFFF，每页1KB。
每条记录32字节，包含版本、递增代数、参数、CRC32和最后写入的提交标志；优先追加，满页才擦另一页，保留上一份有效记录。
参数未变化时不重复写Flash。CRC/提交检查用于忽略断电撕裂记录；不能替代电源电压规范。
没有修改原工程链接配置；应用启动检查完整Load Region末地址，若进入最后2KB，则报FLASH_OVERLAP并禁止使用配置区、禁止控制。验证脚本也检查HEX不覆盖此区。后续大幅扩展工程时应正式缩小链接区或另行规划存储。
不要对末两页存放其他数据；重新烧录是否保留配置取决于下载器擦除方式，整片擦除不会保留。
