# 211 三组按键发送 Demo V3（协议 A2）

本版在原 PA9/PA10 单组按键 Demo 上增加上升、快速按键，并发送完整方向和速度状态。
所有应用改动位于 `211_Project/wu-xian-App`。211 底层 `wu-xian_interface`、原始 RFPDK
参数、配对记录格式、User/main.c 和原 Keil 工程配置均保持原样。
**221 当前已接入本版 A2 无线命令，与有线共用执行状态机。**
当前按有线、无线分别操作进行测试；同时操作时的完整仲裁、来源识别和速度选择尚未解决。
接收端使用方法见 `221_Project/wu-xian-App/README.md`，最新控制版本尚无完整控制板实测结论。

## 打开、编译及运行

打开 `211_Project/Project/GD32E230C8T6.uvprojx`，Rebuild 后烧录发送板。
原主程序继续调用项目自定义函数 `WirelessDemo_Init()`、`WirelessDemo_Process()`，无需修改。
主循环持续调用 Process，不要添加 300ms 等阻塞延时。

上电串口显示 `WIRELESS V3 TX211 PROTO=A2 UART=115200 8N1`。
若 Keil 仍显示旧内容，重新载入磁盘文件，不要用旧编辑缓冲区覆盖新源码。
串口 115200、8N1，PA2=TX、PA3=RX，共地；每 300ms 打印发送统计，并在按键状态变化时输出 KEY。

## 按键和 GPIO 初始化

| 功能 | 一级触点 | 二级触点 | 按下条件 |
| --- | --- | --- | --- |
| 上升 | PB3 | PB4 | 任一触点低 |
| 下降 | PA9 | PA10 | 任一触点低 |
| 快速 | PB5 | PB6 | 任一触点低 |

每组公共端接 GND，输入有外接上拉；软件先开启 GPIOA/GPIOB 时钟，再将六个引脚配置为上拉输入。
使用现有 GD32 官方库读取 GPIO，SPI/串口/定时器继续使用现有驱动与 BSP 初始化。
一级→二级、二级→一级保持同一按键按下；只有该组两个触点都为高才视为完全抬起。
**上升/下降按到二级仍是原方向，不会自动变成快速；快速由 PB5/PB6 独立决定。**
三组按键分别做 10ms 按下和完全抬起消抖，一组抖动不会重置另一组的消抖计时。

| 稳定按键状态 | 发送命令 | COMMAND 十六进制 |
| --- | --- | --- |
| 无方向 / 仅快速 | STOP | 00 |
| 只有上升 | UP | 01 |
| 只有下降 | DOWN | 02 |
| 上升＋快速 | UP_FAST | 05 |
| 下降＋快速 | DOWN_FAST | 06 |
| 上升＋下降（快速任意） | STOP | 00 |

两组方向原始信号同时有效时立即转 STOP，不等待新增方向按键的 10ms 消抖。
冲突消失至少 10ms、稳定按键不再冲突后，可按当前方向恢复，不要求全部松开再按。
方向松开而快速仍按住也发送 STOP；快速单独按下不会产生运动命令。

## 发包方式和协议

发送的是当前完整控制状态，不是“按了一下”的单次事件：

- 任一有效运动状态持续按住时，以 40..60ms 随机起始间隔重复发送。
- 方向/速度改变，优先中止旧状态发送并发送新状态，不等旧包超时。
- 变为 STOP 时，重复发送 3 个 STOP，起始间隔 25..35ms，然后不再占用空口。
- 上电或修改配对配置后，当前无有效方向时也会发送 3 个 STOP，然后空闲。
- 一级/二级切换不改变命令，不产生额外 STOP；下一次周期包仍携带当前完整状态。
- TX_DONE 只证明本地芯片发送完成，没有无线 ACK，不能据此认定接收端已经执行。

8 字节空中有效载荷（CRC 另计）：

| 字节 | 内容 |
| --- | --- |
| 0..3 | 32 位配对 ID，高字节在前；由无线芯片 Node ID 插入 |
| 4 | 协议标识 A2 |
| 5 | COMMAND：仅允许 00/01/02/05/06 |
| 6..7 | 16 位发送序号，高字节在前，65535 后回绕 |

例如 ID=1、快速上升、序号=12：`00 00 00 01 A2 05 00 0C`。
TX FIFO 只写 `A2 05 00 0C` 四字节纯数据，不能把 8 字节都写进去；保留之前实板验证过的行为。
序号在本地 TX_DONE 后增加，用于观察发送，不承担可靠交付或身份认证。

协议常量定义在 `wireless_demo.h`。命令位为 UP=01、DOWN=02、FAST=04，
但 FAST 单独的 04、同时含升降的 03/07，以及其他值都不是合法控制命令。

**旧无线 Demo 使用 A1＋通用 RUN/STOP，与本版 A2 不兼容。**
新的标识保证旧接收 Demo 不会把 A2/01 误当成旧 RUN。
当前 221 已解析 A2 的五种命令，校验 CRC、ID、A2 标识和合法命令，
最后一个有效控制包后 85ms 无更新即撤销无线命令。
无线方向请求经硬件门控、限位等回路后，还需得到对应 PB3/PB4 方向信号，才能由共用执行状态机运行。
221 主程序通过项目自定义函数 `ReceiverApp_Init()`、`ReceiverApp_Process()` 统一接入，
不要直接把 211 的应用源码复制给 221，也不要分别重复初始化有线、无线两个 App。

## 串口日志

```text
KEY up=1 down=0 fast=0 conflict=0 cmd=UP
KEY up=1 down=0 fast=1 conflict=0 cmd=UP_FAST
TX seq=12 cmd=UP_FAST state=UP_FAST data=00 00 00 01 A2 05 00 0C total=12 new=6 err=0
KEY up=1 down=1 fast=1 conflict=1 cmd=STOP
KEY up=0 down=0 fast=0 conflict=0 cmd=STOP
TX IDLE state=STOP total=15 err=0
```

- KEY 的 up/down/fast 是三组消抖后的按键状态，1=按下；conflict 是方向冲突保护状态。
  原始方向冲突立即保护，因此首条冲突日志中 down/up 可能尚未消抖为 1，cmd 已经为 STOP。
- cmd 是最近一次本地发送完成的数据；state 是当前希望发送的状态。两者短暂不一致是可能的。
- `IDLE state=UP` 等可能出现在当前统计窗口尚无 TX_DONE 时，不表示已经松键。
- total/new 是累计/本统计窗口的本地发送完成数，不是接收成功数。
- err 是本地驱动错误统计，不是丢包数；GET 中 LOGDROP 是本地串口日志丢弃数，也不是无线丢包。
- 串口输出沿用中断发送缓冲，不等待整行发送，日志拥堵不会阻塞按键和无线轮询。

## 配对与射频参数

串口以 ASCII 发送，每条命令末尾带 CR、LF 或 CRLF，不要勾十六进制发送。

| 命令 | 作用 |
| --- | --- |
| GET | 查询 ID、频道、频率、配对、保存/无线状态、日志丢弃和 PROTO=A2 |
| SET,1,0 | 配对 ID=1、频道=0，保存并立即应用 |
| DEFAULT | 保存默认 ID=1、CH=0、PAIRED=0，不参与控制，等待重新 SET |
| HELP | 查询命令格式 |

ID 十进制 1..4294967295，频道 0..5。首次烧录/整片擦除/DEFAULT 后必须 SET 才能发送控制包。
普通断电保留配置；重新烧录若整片擦除则会丢失配置。相同配置不重复写 Flash。
旧 A1 版本保存的配置格式与本版相同，不因协议升级主动清除。
当前 221 同样支持 GET、SET、DEFAULT、HELP；两端需配置相同 ID/频道且均为 PAIRED=1、RADIO=OK。
可先在两端发送 GET 核对，配置正确时无需重复 SET。

| 参数 | 211 发送端 | 221 当前接收端 |
| --- | --- | --- |
| 频道 0..5 / MHz | 433.920 / 434.070 / 434.220 / 434.370 / 434.520 / 434.670 | 对应频道相同 |
| 调制 / 速率 / 频偏 | GFSK / 9.6kbps / 10kHz | 相同 |
| 晶振设计值 | 26MHz，40ppm | 26MHz，40ppm |
| Sync / CRC | 2DD4A7B3 / CCITT-16，FFFF | 相同 |
| 包有效载荷 | ID4＋DATA4，固定 8 字节 | 读取完整 8 字节 |
| 应用协议 | A2＋五种方向/速度命令 | 相同，已接入共用执行状态机 |
| 发射功率导出值 | +13dBm | 不适用 |

本次未改动射频寄存器数组、频道步进和原始 .exp。唯一 ID 可以区分配对，不能消除同频道碰撞，
本次没有验证多对并发、通信距离、完整板动作或实测丢包率。
