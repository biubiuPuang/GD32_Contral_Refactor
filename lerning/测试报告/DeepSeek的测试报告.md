### 3.1 C-10/C-11 失败证据

测试输出：

```text
C-10 before RF down   phase=RUN   allow=1 up=1 down=0 fast=0 PB6=0 PB11=0
C-10 during wired UP + RF DOWN   phase=IDLE allow=0 up=0 down=0 fast=0 PB6=1 PB11=0

C-11 before RF up     phase=RUN   allow=1 up=0 down=1 fast=0 PB6=0 PB11=0
C-11 during wired DOWN + RF UP   phase=IDLE allow=0 up=0 down=0 fast=0 PB6=1 PB11=0
```

期望是“继续有线上升/下降”，实际是“全部停止”。这不是安全停止就算通过，因为图片明确要求**有线优先**。

原因在 `wired_port.c` 的混合输入处理：

```c
if(!(input.up && input.down)) {
    input.up   = (uint8_t)(input.up   && (g_remote_applied & 1U));
    input.down = (uint8_t)(input.down && (g_remote_applied & 2U));
}
input.fast = (uint8_t)((g_remote_applied & 4U) && (input.up != input.down));
```

当无线目标为“下降”时，即使有线上升使 PB3 仍然有效，也会被 `g_remote_applied & 1U == 0` 清掉，状态机看到“无方向”，于是停止。

源码注释也已经承认：

```text
Known wired/RF arbitration bug, intentionally deferred.
An opposite wired direction can also be filtered by the RF target.
```

对应文件：`221_Project/you-xian_interface/wired_control.h` 第 61～67 行、`wired_port.c` 第 299～317 行。

### 3.2 C-15 失败证据

测试条件：有线上升一直按住，无线每 40ms 交替发“下降/上升”。

```text
C-15 wired UP held, RF UP/DOWN alternating 40ms:
     KM1-off edges=1, direction-output changes=7,
     double-direction samples=0, final phase=IDLE
```

没有出现双方向同时吸合，这是对的；但**有线上升没有保持**，最后停在 IDLE，因此不满足“优先权稳定”。C-15 不能只按“没有双方向”判通过。

### 4.1 S-08 失败证据

测试输出：

```text
S-08 before reset: RUN
S-08 41ms after reset with UP held:  phase=STARTUP allow=0 PB6=1 PB11=1
S-08 161ms after reset with UP held: phase=RUN     allow=1 PB6=0 PB11=0
S-08 auto-resumed without operator reset=1
```

代码里没有 `fwdgt_init()`、`fwdgt_enable()` 或 `wwdgt_config()` 的应用层调用；`WiredControl_Init()` 只做安全电平预置，随后 50ms 启动保持 + 50ms 回路稳定，然后正常进入控制。没有：

- 复位原因识别
- 异常复位后的禁止锁存
- 故障日志/黑匣子记录
- 复位后的“必须人工确认”流程

所以 S-08 明确不通过。

### 4.3 S-07 的 85ms 边界

现有测试验证了：

- 84ms 仍保持无线急停/运动有效
- 85ms 到达后撤销
- 错误 CRC、错误 ID、旧 A1 标识、非法命令都不能续期
- 无线故障会返回 STOP
- 无线超时后如果仍有有线方向按住，会恢复有线控制

因此“无线通道停止”是通过的；但如果要求“任何来源都全停”，当前设计不满足，因为它是“无线失联后回有线”，不是“全局锁停”。

## 5. 211 发送端单独结论

211 不直接执行电机，只负责发送命令。它的行为通过 `simulate_211_v3.exe` 验证：

- 三组按键：PB3/PB4 上升，PA9/PA10 下降，PB5/PB6 快速
- 每组 10ms 消抖，二级触点不自动表示快速
- 单独快速只发 04，不形成方向
- 升降同时按发 03，接收端按停止处理
- PA8 低有效急停，10ms 确认后发 08，按住持续重发，松开后恢复当前状态
- 方向/速度变化会中止旧包，避免旧命令继续有效
- STOP 连发 3 包后停发，空闲无心跳

**211 本身没有发现与图片矩阵冲突的逻辑。** 但 211 不能弥补 221 的混合仲裁缺陷：有线优先是 221 和硬件 WIRED_IDLE 的职责。

## 6. 必须整改的项目

### P0：不整改不能验收

1. **重做有线/无线混合仲裁**
   - 目标：有线有效时，无线反向/同向请求不能改变有线方向和速度。
   - 现状：`wired_port.c` 用无线目标反向裁剪 PB3/PB4，导致有线被过滤。
   - 难点：PB3/PB4 是“经过限位和硬件选择后的方向反馈”，不是原始有线按键；`WIRED_IDLE` 也没有接 MCU。仅靠现有 GPIO 无法无扰识别来源。
   - 可选方向：利用硬件 WIRED_IDLE 的状态，或增加可观测的“有线请求/空闲”信号；具体方案需要结合“硬件不能再改”的约束确认。

2. **补 S-08 的异常复位安全**
   - 启用独立看门狗，并在复位后识别复位原因。
   - 异常复位后锁存“禁止运行”，不能仅靠 100ms 延时后自动恢复。
   - 增加复位原因/故障日志，至少能区分上电、看门狗、软件复位。
   - 明确复位期间 PA8/9/10、PB6、PB11 的外部上下拉，保证不会出现危险脉冲。

### P1：必须上板补测

3. **S-01**：示波器同时看 T1_RAW、U22 输出、K_PERMIT、CTRL_SAFE、PB6、PA8/9/10，记录从急停断开到 KM1 失电的时间。
4. **S-05/S-06**：实测上限位、下限位断开方向回路时，PB3/PB4、PB6、PA8/9/10 的先后顺序；确认反向退出限位只由硬件允许。
5. **S-09**：无线上升运行中突然给有线下降，记录 K1、APY、KM1、PA8/PA9、PB12/PB13，确认没有双方向、没有窄脉冲。
6. **C-10/C-11/C-15 整改后复测**：不仅看最终状态，还要看 KM1 是否掉落、方向继电器是否抖动。
