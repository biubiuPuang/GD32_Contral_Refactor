### 3.1 C-10/C-11 不通过的证据

模拟输出（`matrix_output.txt`）：

```text
C-10 wired UP running                   phase=RUN   allow=1 out=1/0/0 PB6low=1
C-10 wired UP + RF DOWN held            phase=IDLE  allow=0 out=0/0/0 PB6low=0
       first allow=0 after 1 ms; down relay ever=0; final=IDLE
C-10 RF stopped, wired UP still held    phase=RUN   allow=1 out=1/0/0 PB6low=1
```

原因在 `221_Project/you-xian_interface/wired_port.c:313-318`：

```c
if(!(input.up && input.down)) {
    input.up   = (uint8_t)(input.up   && (g_remote_applied & 1U));
    input.down = (uint8_t)(input.down && (g_remote_applied & 2U));
}
input.fast = (uint8_t)((g_remote_applied & 4U) && (input.up != input.down));
```

无线目标是“下降”时，有线上升仍然有效的 PB3 被 `g_remote_applied & 1U == 0` 清掉，状态机看到“无方向”，于是 `Wired_BeginStop()` 撤 PB6、50ms 后撤方向继电器。**这不是“有线优先”，而是“无线反向请求把有线也停掉”。** 源码自己也标注了这是已知未修问题（`wired_control.h:61-67`）。

### 3.2 C-15 不通过的证据

```text
C-15 wired UP + RF alternating 40ms     phase=IDLE  allow=0 out=0/0/0 PB6low=0
       2000ms: RUN_up=0 ms, no-permit=2000 ms, direction-output changes=25, double-direction=0
C-15 RF activity stopped, wired UP still held  phase=RUN  allow=1 out=1/0/0
```

没有出现双方向同时吸合（安全），但**有线上升 2 秒内一秒都没跑**，无线一停马上恢复。无线每变一次命令，`SetRemoteCommand()` 都会先停一次（KM_OFF 50ms + RELEASE 30ms + 稳定 50ms/20ms，见 `wired_control.c:131-159` 与 `wired_config.h:6-13`），40ms 一变的节奏下永远回不到 RUN。这就是“反复切换”，不满足“优先权稳定”。

### 4.1 S-02 的补充（非锁存）

```text
S-02 wired E-stop released, RF 08 still streaming   PB11high=1
S-02 no more 08 packets                             PB11 auto-released (last 08 + ~84 ms)
```

只要 08 还在持续到达，撤销是保持的，满足本条；但**无线急停不锁存**：最后一条 08 之后约 84ms，PB11 自动放行。如果操作者一直按着无线急停而射频链路断了，CTRL_SAFE 会被恢复（运动仍因超时是 STOP，但禁止没有被保持）。这是设计取舍，需要安全评审确认是否接受。

S-08 after reset                      phase=RUN     allow=1 out=1/0/0 PB6low=1

## 5. 211 发送端单独结论

211 不直接驱动电机，只发 A2 命令，自身测试全部通过：

- 三组按键（PB3/PB4 上升、PA9/PA10 下降、PB5/PB6 快速），每组 10ms 双边沿消抖，一级/二级等效，二级不自动代表快速；
- 单独快速只发 04，不形成方向；升降同时按立即发 03，不等对向键消抖；
- PA8 低有效急停：10ms 确认后发 08，按住持续重发，优先于方向/快速；
- 方向/速度变化先中止旧包，再发新状态；停止包发 3 次后停发，空闲无心跳；
- 64 种六触点组合真值表、重复发送间隔 40~60ms、STOP 25~35ms × 3、序号、A2 标识均通过。

**211 本身没有发现与矩阵冲突的逻辑**；C-10/C-11/C-15 的失败在 221 的混合输入处理和复位策略，211 无法弥补。

## 6. 需要整改 / 需要上板的项目

### P0（不整改不能验收）

1. **重做 221 混合输入处理，去掉“用无线目标裁剪 PB3/PB4”的做法**（`wired_port.c:299-318`）。
   - 目标：有线有效时，无线反向/同向请求不能改变有线方向和速度；至少不能把正在运行的有线动作停掉。
   - 难点：PB3/PB4 是“经过限位和硬件选择后的共用方向反馈”，`WIRED_IDLE` 没有接 MCU，软件无法直接区分来源；同向不同速（有线慢升 + 无线快升）受硬件可观测性限制。
   - 这条需要先定策略再改代码，不能只把过滤删掉了事（否则无线 FAST 可能叠到有线慢速上）。

2. **补 S-08 的异常复位安全**：读复位原因、异常复位后锁存禁止（不能 130ms 后自动恢复）、记录复位/故障日志。

3. **C-15 的优先级稳定性**：无线频繁操作时不能让有线一直停；至少要保证“无线命令变化不打断已确认的有线运行”。
