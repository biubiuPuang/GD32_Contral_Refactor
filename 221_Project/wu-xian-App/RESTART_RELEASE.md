# 异常复位后等待松键

本次只处理异常复位后的自动恢复。有线/无线混合仲裁及同向快速残留仍按原版本保留。

## 行为

- 211、221 均使用现有 GD32 官方库读取 FWDGT、WWDGT、软件复位标志，读取后清除所有复位标志，避免旧标志影响下一次启动。
- 上述任一原因触发等待松键；普通通电启动保持原规则，方向已按住仍可按原有准备时序运行。外部复位脚、选项字节装载复位不在本次新增触发范围。
- 211 异常复位后，方向/快速仍按住只发送普通 STOP；全部方向/快速触点经消抖及松开确认后，再次按键才发送运动命令。PA8 无线急停始终优先，等待松键期间也可发 08。
- 221 异常复位后，有线侧等待 PB3/PB4/PB5 全部无效、回路启动稳定且持续 10ms，再允许新的按键动作。期间 PB6 不许可、方向/快速输出关闭。PB11 会按原启动时序放行，使方向输入回路可观测；不能用 PB11 一直断电来判断松键。
- 221 的无线侧必须收到 CRC、ID、A2、命令检查均通过的**新鲜 STOP=00 包**，才允许后续运动包。85ms 超时、无线故障、未配对、非法 STOP、03/04 状态均不能当作松键。
- 有线和无线侧分别确认释放；无线离线不会让有线永久等待。无线急停、维护禁止、输出故障继续独立生效，松键不会清除它们。
- 不写入新的 Flash 记录，不更改配对格式、射频参数、频道、底层 BSP、工程配置、主程序和看门狗喂狗顺序。

## 可观测范围

PB3/PB4 是经过实体急停、限位等回路的共用方向反馈，不是原始有线按键。新增限制可以阻止**反馈仍有效**的按住方向在异常复位后恢复；但实体急停或限位遮蔽按键信号时，现有硬件无法区分“真正松开”和“回路阻断”，不能保证这类情况下的真实松键识别。完整保证需要原始按键或独立状态输入；本次没有改硬件。

无线空闲无心跳的旧策略保留。若接收端异常复位时遥控器已空闲且三个 STOP 已发完，接收端可能尚未看到松键；首次按下会被限制，松开产生 STOP 后，再按才执行。普通通电不受此限制。

## 串口日志

异常启动按原因打印一次：

```text
RESET FWDGT WAIT RELEASE
RESET WWDGT WAIT RELEASE
RESET SOFTWARE WAIT RELEASE
```

只打印实际存在的原因。确认松键时分别打印一次 `RESTART KEYS RELEASED`（211）、`RESTART WIRED RELEASED` / `RESTART RF RELEASED`（221）。均复用现有非阻塞日志队列；无跨断电故障存储。

## 验证

在工程根目录运行：

```powershell
python 221_Project/wu-xian-App/validation/check_restart.py
```

此入口重新编译真实应用源码的主机测试，再顺序执行 211、221 的 Keil 完整重编译；不打开串口、不烧录。输出默认位于该脚本旁的 `restart_results`，可用 `--output` 指定目录；`--no-build` 仅运行模拟。

覆盖正常上电按住两端方向、三种异常复位原因、粘滞标志清除、上下方向/两级触点/快速/冲突、持续按住及换方向不能解除、释放抖动、重新按键、有效 STOP 与超时/错误 STOP 区别、无线急停优先、无线离线时有线可恢复、维护禁止隔离及计时回绕。也复用原有 20 万步执行互锁、收包/Flash/UART 和 211 低功耗全部回归。

本机模拟不产生实际 MCU 看门狗复位，不能证明复位瞬间电气脉冲、外部触点状态或机械停机时间。实板应分别测试正常断电重上电、运行中停止喂狗触发复位、持续按住、松开再按，以及两端分别异常复位。
