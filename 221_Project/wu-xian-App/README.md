## 配对和测试步骤

1. 两端串口均为 115200、8N1，ASCII，命令末尾带回车或换行，不勾选十六进制发送。
   按之前设备对应关系，COM2 是 211 发送端，COM18 是 221 接收端。
2. 分别发送 GET，确认两端 `PROTO=A2`、相同 ID/CH、`PAIRED=1`、`RADIO=OK`。
   若未配对或参数不一致，在两个串口分别发送 `SET,1,0`，等待 `OK SAVED APPLIED`。
3. 先不按无线按钮，单独测试原有有线升/降/快速及停止；无线未配置或故障不禁止正常有线。
4. 松开有线按钮，分别测试无线升、降、升＋快速、降＋快速，观察动作和日志。
5. 松开方向，确认停止。按住方向时关闭发送板电源，确认接收端报告超时并撤销输出许可。
6. 分别检查完整控制板的方向回路、限位、实体急停及解除后的当前有效命令恢复行为。
7. 分别在有线、无线运行时按下遥控器 PA8 急停，检查周期 `stop model`、PB11/PB6 高及无线请求撤销。
   保持通信时应持续禁止运行；松开后按当前有效命令恢复，不要求方向键松开重按。
8. 无线急停期间关闭遥控器电源：最后一个有效包后 85ms 撤销无线急停并恢复有线处理，
   不是恢复旧无线运动。有线实体急停仍按下时继续禁止；无有效运动输入时保持停止。
   此项是用户确认的功能行为；本轮只做模拟/编译，尚未完成实板验证。

当前仍支持 GET、SET,<ID>,<CH>、DEFAULT、HELP，没有无线配置或出厂锁定。
SET 保存并立即应用；DEFAULT 保存 ID=1/CH=0/PAIRED=0，仅关闭无线参与，不禁止有线。
配置保存在原末两页 Flash，普通断电保留；整片擦除会清除。ID 十进制 1..4294967295，CH=0..5。
显式 SET/DEFAULT 属于维护操作，先暂时禁止执行输出，再改 Flash/无线参数，完成后解除软件禁止。
保存失败、重载和配置错误仍保留原有检查，不以串口收到任何文字作为运动命令。

## 控制路径

```text
有线：PB3/PB4 方向回路＋PB5 快速 → 共用继电器执行状态机
无线：CRC/ID/A2/命令校验 → PB12/PB13 请求 → 硬件门控、限位等回路
      → PB3/PB4 匹配方向反馈 → 共用继电器执行状态机
无线急停：相同收包校验 → 独立无线禁止原因 → PB6/PB11 高、撤无线请求、按原时序释放继电器
```

| 无线 COMMAND | 含义 | 请求输出 | 快速执行 |
| --- | --- | --- | --- |
| 00 | STOP | PB12/PB13 均低 | 退出运行 |
| 01 | 上升 | PB12 高、PB13 低 | 慢速 |
| 02 | 下降 | PB12 低、PB13 高 | 慢速 |
| 03 | 上下方向冲突状态 | PB12/PB13 均低 | 无线停止，绝不作为双方向执行 |
| 04 | 单独快速状态 | PB12/PB13 均低 | 无线停止，绝不单独驱动快速继电器 |
| 05 | 快速上升 | PB12 高、PB13 低 | PA10 低 |
| 06 | 快速下降 | PB12 低、PB13 高 | PA10 低 |
| 08 | 全局无线急停 | PB12/PB13 均低，PB6/PB11 高 | 按停止时序释放方向和快速继电器 |

08 是独立完整命令，09/0A/0D/0E 等混合值非法。普通 STOP=00 不持续禁止有线。

### 无线急停有效期及恢复

- 无线急停与有线实体急停均优先于普通运动。实体急停独立由硬件禁止；无线急停由软件公共禁止输出执行。
- 08 按 40..60ms 周期重复，持续收到有效包就保持全局无线禁止，PB11 不会切断 MCU/无线芯片供电，收包持续运行。
- 收到新的合法非急停状态，或最后有效包后 85ms 超时、无线故障、取消配对时，清除无线急停原因。
  失联后回到有线处理：有线按住则按现有执行准备恢复，无输入则停止；有线实体急停仍按着则硬件继续禁止。
- 无线急停不写 Flash，接收端重启不恢复历史无线命令；重新收到什么有效状态就处理什么状态。
- 无线急停、维护禁止和锁存输出故障分别管理；无线解除/超时不能清掉其他禁止原因。
- 解除无线禁止先按状态机放行 PB11、等待回路稳定，再判断输入，不能在 PB11 高时等待 PB3/PB4 恢复。
- 用户已确认的失联策略会允许有线恢复，即使失联遥控器的急停仍物理按着；不把无线超时视作已确认松开按键。

无线方向意图不能替代真实回路反馈：无线上升必须 PB3 有效且没有反向冲突，下降必须 PB4 有效。
仅收到数据、没有对应方向反馈时保持等待，不放行 PB6，也不显示无线运行完成。
软件仍不能通过 GPIO 得知 KM1 实际触点闭合或电机已经运动。
实体急停由硬件禁止，MCU 没有独立实体急停状态输入；日志不虚构 ESTOP_PRESSED/RELEASED。
急停/限位解除后，如当前无线命令仍持续有效或有线仍按住，可经过执行准备恢复，不要求松开再按。
无线命令已过期时，解除急停也不能恢复旧无线命令。

### 停止、换向与超时

- 无线运动或急停按住期间，211 每 40..60ms 重复完整状态；221 只接受 CRC、ID、A2 标识及八种状态都正确的包。
- 无线运动命令最后一个有效包后 **85ms** 没有更新，清除无线运动，立即撤 PB6 许可和 PB12/PB13 请求。
  无线急停过期按上一节清除其禁止原因，重新经过回路稳定/执行准备后允许有线控制。
  错误 ID、旧 A1 协议、CRC 错误、非法命令不续期。
- 收到 STOP、无线故障、配置维护时，也清除无线运动请求；不把普通无线失联连接到公共 PB11 禁止有线。
- 普通有线逻辑沿用原参数：有效确认 10ms，输入失效立即撤 PB6。
- 方向/速度/控制来源改变先撤 PB6、撤无线请求，原方向/速度继电器保留 50ms，再全部释放等待 30ms。
- 执行器空闲后，提出新的无线方向请求，按初始参考值等待 **20ms**，再采样对应方向反馈。
  方向反馈稳定 10ms、继电器准备 30ms 后，才放行 PB6。
- 退出无线后也等回路稳定再恢复有线采样，避免把继电器释放期间的残留反馈误认作有线按键。
- 无线持续有效但限位/急停使方向反馈消失时，执行器立即停止；不会用收到的命令强行合成反馈。

所有等待均在状态机中进行，主循环持续采样，无 500ms 阻塞延时。
50/30/30ms、20ms 仍是初始参考时序，未测实际触点和机械停止时间。
85ms 是软件无线有效期，不代表已实测保证按键到机械动作/停机在 100ms 内，换向还需完成释放时序。

## 串口日志

上电无线初始化结束打印一次版本、CFG（含频率）和INIT结果；GET/SET/DEFAULT/HELP及命令错误即时回复。
普通按键变化、收包、超时事件、统计明细不再自动输出，也不周期重复配置。

每1000ms在执行状态更新后分别输出动作行和连接行，均以 `\r\n` 结束：

| 当前执行/按键状态 | 动作行 |
| --- | --- |
| 有线上升 / 下降 | `you-xian up` / `you-xian dowm` |
| 有线快速上升 / 下降 | `you-xian fast up` / `you-xian fast dowm` |
| 无线上升 / 下降 | `wu-xian up` / `wu-xian dowm` |
| 无线快速上升 / 下降 | `wu-xian fast up` / `wu-xian fast dowm` |
| 单独有线快速 / 单独无线快速 | `you-xian fast` / `wu-xian fast` |
| 当前方向冲突 | `error model` |
| 有效无线急停/软件禁止 | `stop model` |
| 无线升/降请求未获得对应方向信号 | `cant up model` / `cant dowm model` |
| 无有效控制请求 | `sleep model` |
| 执行输出故障 | `wu-xian not connect` |
| 继电器切换、释放、回路稳定、方向准备 | 不输出动作行，连接行照常输出 |

`cant` **只表示无线请求未通过方向回路**，原因可能是限位、实体急停或其他硬件阻断，
不能准确认定为上/下限位触发。有线原始方向键和实体急停没有独立MCU输入，不虚构其检测状态。
动作行表示软件执行状态，不能证明电机实际运动。混合来源和速度仍保留已知仲裁BUG。

连接行：最近85ms内收到通过CRC/ID/A2/合法状态校验的包，且本机无线/执行无故障时打印
`wu-xian connect ing`；否则打印 `wu-xian not connect`。STOP=00包也能刷新该状态，非法包不刷新。
**已知限制按用户要求保留：无按键时211发送3个STOP后停止发包，未增加空闲心跳，
因此空闲也会显示not connect；这是近期有效收包状态，不能证明真正断联或双向连接。**

无线初始化/SPI/寄存器检查失败或未配置时，每1000ms额外打印 `ERR RADIO <具体原因>`；
输出锁存器异常额外打印 `ERR EXEC OUTPUT_MISMATCH`。软件内部状态异常打印 `ERR EXEC INTERNAL_STATE`。
错误提示按当前故障持续输出，恢复后停止；输出故障仍按原策略锁存，不被无线解除/超时清除。
无线异常时正常有线动作仍按实际执行状态显示，同时打印连接异常及无线错误。

例如正常无线上升的一个周期：

```text
wu-xian up
wu-xian connect ing
```

日志统一进入USART1非阻塞发送队列；队列拥堵丢整行，不等待发送、不影响急停及执行。
短于1000ms的动作可能不出现在快照里；1000ms仅影响打印，控制、收发和85ms超时持续实时处理。
两端均须升级支持03/04的本版固件，旧A2接收端会拒绝新状态。

| --- | --- | --- |
| 应用协议 | A2；00/01/02/03/04/05/06/08 | 相同，仅接收八种合法状态 |

## 代码与资源

- `wu-xian-App/receiver_app.c`：主循环协调、无线急停同步、配置维护联锁。
- `wu-xian-App/wireless_demo.c`：CMT2219B 接收、A2 校验、85ms 有效期、配对保存及统一串口队列。
- `you-xian_interface/wired_control.c`：原共用继电器状态机，逻辑源文件本次未修改。
- `you-xian_interface/wired_port.c`：共用 GPIO 输出与反馈检查、无线请求切换、独立无线急停原因、状态日志。
- `you-xian_interface/wired_config.h`：保留原等待值，新增 RF 回路稳定初值 20ms。

安全执行 GPIO 先初始化，再初始化无线。SPI 为 PA4/PA5/PA7/PB0，不占 PB12/PB13 请求脚。
TIMER13 为执行毫秒时基，TIMER2 为无线 10kHz 时基，USART1_IRQHandler 由无线服务唯一拥有。
沿用现有 SysTick 阻塞短延时 BSP 给无线 SPI 使用，主循环不调用长延时。
无线离线时重试初始化只在执行器空闲/禁止状态进行，避免缺失无线芯片时周期打断正在运行的有线动作。
配置 Flash 仍为 0x0800F800..0x0800FFFF，镜像重叠检查与追加式 CRC/提交记录保留。
