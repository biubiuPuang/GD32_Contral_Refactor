## 配对和测试步骤

1. 两端串口均为 115200、8N1，ASCII，命令末尾带回车或换行，不勾选十六进制发送。
   按之前设备对应关系，COM2 是 211 发送端，COM18 是 221 接收端。
2. 分别发送 GET，确认两端 `PROTO=A2`、相同 ID/CH、`PAIRED=1`、`RADIO=OK`。
   若未配对或参数不一致，在两个串口分别发送 `SET,1,0`，等待 `OK SAVED APPLIED`。
3. 先不按无线按钮，单独测试原有有线升/降/快速及停止；无线未配置或故障不禁止正常有线。
4. 松开有线按钮，分别测试无线升、降、升＋快速、降＋快速，观察动作和日志。
5. 松开方向，确认停止。按住方向时关闭发送板电源，确认接收端报告超时并撤销输出许可。
6. 分别检查完整控制板的方向回路、限位、实体急停及解除后的当前有效命令恢复行为。

当前仍支持 GET、SET,<ID>,<CH>、DEFAULT、HELP，没有无线配置或出厂锁定。
SET 保存并立即应用；DEFAULT 保存 ID=1/CH=0/PAIRED=0，仅关闭无线参与，不禁止有线。
配置保存在原末两页 Flash，普通断电保留；整片擦除会清除。ID 十进制 1..4294967295，CH=0..5。
显式 SET/DEFAULT 属于维护操作，先暂时禁止执行输出，再改 Flash/无线参数，完成后解除软件禁止。
保存失败、重载和配置错误仍保留原有检查，不以串口收到任何文字作为运动命令。

## 控制路径

```text
有线：PB3/PB4 方向回路＋PB5 快速 → 共用继电器执行状态机
无线：CRC/ID/A2/命令校验 → PB12/PB13 请求 → 硬件门控、限位等回路
      → PB3/PB4 匹配方向反馈 → 共用继电器执行状态机
```

| 无线 COMMAND | 含义 | 请求输出 | 快速执行 |
| --- | --- | --- | --- |
| 00 | STOP | PB12/PB13 均低 | 退出运行 |
| 01 | 上升 | PB12 高、PB13 低 | 慢速 |
| 02 | 下降 | PB12 低、PB13 高 | 慢速 |
| 05 | 快速上升 | PB12 高、PB13 低 | PA10 低 |
| 06 | 快速下降 | PB12 低、PB13 高 | PA10 低 |

无线方向意图不能替代真实回路反馈：无线上升必须 PB3 有效且没有反向冲突，下降必须 PB4 有效。
仅收到数据、没有对应方向反馈时保持等待，不放行 PB6，也不显示无线运行完成。
软件仍不能通过 GPIO 得知 KM1 实际触点闭合或电机已经运动。
实体急停由硬件禁止，MCU 没有独立实体急停状态输入；日志不虚构 ESTOP_PRESSED/RELEASED。
急停/限位解除后，如当前无线命令仍持续有效或有线仍按住，可经过执行准备恢复，不要求松开再按。
无线命令已过期时，解除急停也不能恢复旧无线命令。

### 停止、换向与超时

- 无线按住期间，211 每 40..60ms 重复完整状态；221 只接受 CRC、ID、A2 标识及五种命令都正确的包。
- 最后一个有效控制包后 **85ms** 没有更新，清除无线命令，立即撤 PB6 许可和 PB12/PB13 请求。
  错误 ID、旧 A1 协议、CRC 错误、非法命令不续期。
- 收到 STOP、无线故障、配置维护时，也清除无线运动请求；不把普通无线失联连接到公共 PB11 禁止有线。
- 普通有线逻辑沿用原参数：有效确认 10ms，输入失效立即撤 PB6。
- 方向/速度/控制来源改变先撤 PB6、撤无线请求，原方向/速度继电器保留 50ms，再全部释放等待 30ms。
- 执行器空闲后，提出新的无线方向请求，按初始参考值等待 **20ms**，再采样对应方向反馈。
  方向反馈稳定 10ms、继电器准备 30ms 后，才放行 PB6。
- 退出无线后也等回路稳定再恢复有线采样，避免把继电器释放期间的残留反馈误认作有线按键。
- 无线持续有效但限位/急停使方向反馈消失时，执行器立即停止；不会用收到的命令强行合成反馈。

所有等待均在状态机中进行，主循环持续采样，无 500ms 阻塞延时。
50/30/30ms、20ms 仍是初始参考时序，未测实际触点和机械停止时间。
85ms 是软件无线有效期，不代表已实测保证按键到机械动作/停机在 100ms 内，换向还需完成释放时序。

## 串口日志

每 **500ms** 输出执行状态和无线接收统计；命令变化、超时、配置操作另有事件/回复。
两种日志共用一个 USART1 中断发送队列，避免内容穿插；队列拥堵会丢日志，不阻塞执行循环。

```text
RECEIVER V3 RX221 PROTO=A2 UART=115200 8N1
EVENT UP PACKET
RX seq=12 cmd=UP state=UP data=00 00 00 01 A2 01 00 0C total=12 new=10 err=0
t=1000 wu xian model up speed=slow phase=RUN reason=NONE PB3/4/5=011 PB6/11=00 PA9/8/10=011 RF=UP PB12/13=10 drop=0
EVENT STOP TIMEOUT
```

| 日志 | 含义 |
| --- | --- |
| sleep model | 无有效执行请求，当前空闲 |
| wait model | 来源切换/回路稳定/方向准备，或有无线意图但反馈未满足 |
| you xian model up/down | 有线路径执行准备完成，软件已放行 PB6 |
| wu xian model up/down | 无线路径执行准备完成，软件已放行 PB6 |
| stop model | 软件禁止、方向冲突或停止释放过程中 |
| EVENT UP/DOWN/... PACKET | 收到并接受无线命令，尚不等于执行器运行 |
| EVENT STOP TIMEOUT | 无线命令过期 |

`RX state` 是无线解析层的当前命令，不是电机运行状态；应结合执行行的 phase、PB6/11 判断。
`PB3/4/5` 打印真实采样电平，RF 快速来自无线命令，不会伪装成 PB5 低。
`PB12/13` 是软件提出的无线请求，仍受硬件门控；不是实际机械动作反馈。
运行日志只在 RUN 且输出准备完成时出现。短于 500ms 的停止过渡可能没有周期快照，但有命令/超时事件。
`err` 是本地无线错误统计，不能直接换算丢包率；LOGDROP/drop 是本地日志丢弃，不是无线丢包。
同时操作有线和无线时，来源标签与速度选择存在本轮明确暂不处理的歧义，不能作为仲裁正确的证明。

## 两端兼容参数

| 参数 | 211 发送端 | 221 接收端 |
| --- | --- | --- |
| 应用协议 | A2；00/01/02/05/06 | 相同，仅接收五种合法命令 |
| 频道 0..5 / MHz | 433.920 / 434.070 / 434.220 / 434.370 / 434.520 / 434.670 | 对应相同 |
| 配对编号 | 串口设置的 32 位 ID | 相同 ID，硬件及应用检查 |
| 调制 / 速率 / 频偏 | GFSK / 9.6kbps / 10kHz | 相同 |
| 无线晶振 / 设计容差 | 26MHz / 40ppm | 相同 |
| Sync / CRC | 2DD4A7B3 / CCITT-16，FFFF | 相同 |
| Payload | ID4＋DATA4，共 8 字节，不含 CRC | 相同 |
| FIFO 访问 | 只写后 4 字节，硬件插入 ID | 读取完整 8 字节 |
| 发射功率导出值 | +13dBm | 不适用 |
| AFC_OVF_TH | 不适用 | 应用保持覆盖为 21(15h) |

本次不改变 .exp、96 字节参数数组或底层 SPI 驱动，不代表已经验证距离、多对并发或实测丢包率。

## 代码与资源

- `wu-xian-App/receiver_app.c`：主循环协调、配置维护联锁。
- `wu-xian-App/wireless_demo.c`：CMT2219B 接收、A2 校验、85ms 有效期、配对保存及统一串口队列。
- `you-xian_interface/wired_control.c`：原共用继电器状态机，逻辑源文件本次未修改。
- `you-xian_interface/wired_port.c`：共用 GPIO 输出与反馈检查、无线请求切换、状态日志。
- `you-xian_interface/wired_config.h`：保留原等待值，新增 RF 回路稳定初值 20ms。

安全执行 GPIO 先初始化，再初始化无线。SPI 为 PA4/PA5/PA7/PB0，不占 PB12/PB13 请求脚。
TIMER13 为执行毫秒时基，TIMER2 为无线 10kHz 时基，USART1_IRQHandler 由无线服务唯一拥有。
沿用现有 SysTick 阻塞短延时 BSP 给无线 SPI 使用，主循环不调用长延时。
无线离线时重试初始化只在执行器空闲/禁止状态进行，避免缺失无线芯片时周期打断正在运行的有线动作。
配置 Flash 仍为 0x0800F800..0x0800FFFF，镜像重叠检查与追加式 CRC/提交记录保留。
