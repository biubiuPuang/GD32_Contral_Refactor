# 221 有线控制测试版本

打开原工程 `221_Project/Project/GD32E230C8T6.uvprojx`，编译、烧录接收控制板。
`User/main.c` 已改为调用下面两个**项目自定义函数**，无需再手动替换：

```c
WiredControl_Init();
while (1) {
    WiredControl_Process();
}
```

本次只实现有线执行。PB12/PB13 始终为低，禁用无线方向请求；无线 Demo 源文件保留，
但 `wireless_demo.c` 在此 Keil 工程中设为不参与编译。本固件不运行无线收包、心跳、
配对串口命令，不改写无线参数 Flash。211 工程及两端无线底层文件均未修改。

## 输入、输出

| GPIO | 用途 | 有效电平 |
| --- | --- | --- |
| PB3 | 经限位等回路后的上升方向信号 | 低 |
| PB4 | 经限位等回路后的下降方向信号 | 低 |
| PB5 | 有线快速请求 | 低 |
| PA9 | 上升继电器驱动 | 低 |
| PA8 | 下降继电器驱动 | 低 |
| PA10 | 快速继电器驱动 | 低 |
| PB6 | KM1 运行许可 | 低 |
| PB11 | 公共软件禁止 | 高 |
| PB12/PB13 | 无线升/降请求 | 本版固定低 |

GPIO 初始化先开启 GPIOA/GPIOB 时钟，先预写安全电平，再配置输出模式。
默认 PB6/PB11 高、PA8/PA9/PA10 高、PB12/PB13 低；输入 PB3/4/5 配置上拉。
串口沿用现有 BSP 的 `usart_init(115200)`，其内部开启 USART1 与 GPIO 时钟。
计时使用 TIMER13，先开定时器时钟，再配置为 2kHz，自由计数折算毫秒。
没有修改 SysTick、中断处理文件和无线底层。主循环禁止添加阻塞延时。

## 动作规则

- PB3 单独有效：上升；PB4 单独有效：下降。
- PB3/PB4 同时有效：方向冲突，立即撤 PB6，完成继电器释放，禁止运行。
  冲突解除后按当前有效方向恢复，不要求先全部松开。
- 只有快速，没有方向：不运行、不吸合快速继电器。
- 输入有效持续 10ms 才接受；输入失效立即取消对应状态，不等待释放消抖。
  一次短暂方向中断也会走完整停止过程，不因信号马上恢复就跳过切换等待。
- 快速必须依附有效方向；升/降、慢/快任何改变均通过下面的停机切换流程。
- 实体急停由硬件独立禁止运行。解除后按当前有效输入恢复，允许按键一直按住；
  上电时已经按住方向键也允许经过启动及方向准备后运行。

### 时序与状态

`wired_config.h` 集中保存参数：

| 参数 | 初始值 | 含义 |
| --- | --- | --- |
| STARTUP_HOLD | 50ms | 初始化安全输出保持，PB11 高 |
| PERMIT_SETTLE | 50ms | PB11 放行后等待操作回路稳定，PB6 仍高 |
| INPUT_ON | 10ms | 输入有效确认 |
| KM_OFF | 50ms | 撤 PB6 后保留原方向/速度继电器驱动 |
| RELAY_RELEASE | 30ms | 全部方向/速度继电器释放后的等待 |
| RELAY_PREPARE | 30ms | 新方向/速度继电器驱动设置后等待，再放行 PB6 |
| REPORT | 500ms | 状态日志周期 |

从空闲开始：确认输入 → 设置方向/速度 → 准备 30ms → PB6 低。
停止或换向换速：PB6 先高 → 等 50ms → PA8/9/10 全高 → 等 30ms → 空闲。
仍有有效请求时，再设置新方向/速度，等 30ms 才放行。
等待期间持续采样，新命令不会绕过释放过程；方向准备期间请求消失也会取消启动。
这些是旧程序参考时序和本次初值，尚未通过实物触点或电机停机测量验证。

普通松键/方向冲突不拉高 PB11，以保持输入可观测性，避免软件切断回路后等待按键的死锁。
预留的项目自定义函数 `WiredControl_SetSoftwareStop(1)` 主动禁止，传 0 解除；
只供主循环代码调用，本版不提供串口动作命令。软件禁止会立即置 PB6/PB11 高，
继电器仍按停机时序释放，解除后重新等待操作回路稳定。
输出锁存器读回不一致会保持软件禁止，需复位排查；不会自动恢复或继续打印运行状态。

## 串口日志

115200、8N1，PA2=TX、PA3=RX，共地。上电输出一条初始化状态，之后每 500ms 一条。
日志使用 ASCII，非阻塞轮询逐字节发送；不使用等待式 printf。串口阻塞时丢弃新的整条日志，
`drop` 递增，控制持续执行。`drop` 与无线丢包无关。

```text
t=0 stop model speed=slow phase=STARTUP reason=STARTUP PB3/4/5=111 PB6/11=11 PA9/8/10=111 RF=OFF drop=0
t=500 sleep model speed=slow phase=IDLE reason=NO_DIRECTION PB3/4/5=111 PB6/11=10 PA9/8/10=111 RF=OFF drop=0
t=1000 you xian model up speed=slow phase=RUN reason=NONE PB3/4/5=011 PB6/11=00 PA9/8/10=011 RF=OFF drop=0
```

| 日志 | 条件 |
| --- | --- |
| `sleep model` | 执行器空闲，无有效方向；单按快速也不会运行 |
| `wait model` | 输入确认、操作回路稳定或新方向准备中，尚未放行 PB6 |
| `you xian model up` | 上升执行状态已进入 RUN，PB6 低、PB11 低，输出锁存器读回一致 |
| `you xian model down` | 下降执行状态已进入 RUN，PB6 低、PB11 低，输出锁存器读回一致 |
| `stop model` | 启动禁止、停止释放过程、方向冲突、软件禁止或内部异常 |

`PB3/4/5`、`PB6/11`、`PA9/8/10` 按标出的脚位顺序打印 MCU 侧高低电平。
`speed` 表示当前继电器速度接法，停止释放等待中可能仍显示 fast，此时 PB6 已禁止。
`reason=NO_DIRECTION` 可能是松键、限位、实体急停或操作回路断电，不能据此确认是哪一种。
当前硬件没有独立实体急停状态输入，不能准确打印 `ESTOP_PRESSED/RELEASED`。
短于 500ms 的动作可能不落在周期快照上，不能把日志条数当作动作次数。

RUN 表示软件已完成输出准备与放行，不代表已测得接触器实际吸合或电机运动。
完整控制板仍必须满足实体急停、限位和外部硬件的运行条件。

## 文件与后续无线接口

- `wired_control.c/.h`：无外设依赖的执行状态机、状态命名，以及板级入口声明。
- `wired_port.c`：实际 GPIO、TIMER13、BSP 串口初始化及非阻塞日志。
- `wired_config.h`：所有等待参数。
- `validation/`：软件测试、构建日志及改动前 main/工程文件备份，运行工程不依赖此目录。

后续有线/无线先做来源仲裁，再共用一套继电器执行，不能各自直接写 PA8/9/10、PB6/PB11。
PB3/PB4 始终是共用方向信号，并非独立有线原始按键或触点反馈；本版只有在 PB12/13 为低时
将其作为有线方向处理。无线失联撤销无线请求，不能把它直接接到全局软件禁止上影响有线。
本版不提前实现不具备独立来源检测条件的自动无线仲裁，也不初始化旧无线 Demo。
未来串口、计时、心跳与执行循环需统一接入，不能直接同时调用两套 App_Init/Process。

## 验证及完整板测试

命令行运行：

```powershell
python 221_Project/you-xian_interface/validation/check_wired.py
```

脚本检查受保护源文件哈希，使用本机 GCC 测试真实控制逻辑和实际端口源码的模拟外设，
再使用本机 Keil 完整重编译原 221 工程。测试不连接硬件、不烧录。
覆盖启动、输入抖动、立即停止、升降/快速、冲突恢复、换向换速顺序、软件禁止、短暂禁止、
计时回绕、GPIO 预载和操作顺序、72MHz 预分频、500ms 日志、串口背压和输出读回异常。

完整控制板首次测试应核对默认电平、升降及快速极性、松键停机、换向换速等待、
升降冲突、实体急停按住时禁止运行、急停解除后的按住恢复、上下限位以及上电按住的行为。
通过日志观察软件状态，同时实测相关继电器和 KM1；软件测试不代替这一步。
