## 4. 211 发送板硬件与按键规则

CMT2119B **只发送**，CMT2219B **只接收**，没有无线回传、ACK 或真正的双向连接确认。
两端无线芯片都通过四根线软件 SPI：CSB=PA4、FCSB=PB0、SCLK=PA5、SDIO=PA7。
无线芯片 GPIO1/2/3 未连接，采用 SPI 查询标志。
USART1 使用 PA2=TX、PA3=RX，115200、8N1。

| 211 按键功能 | 一级触点 | 二级触点 |
| --- | --- | --- |
| 上升 | PB3 | PB4 |
| 下降 | PA9 | PA10 |
| 快速 | PB5 | PB6 |

每组公共脚接 GND，触点输入外接上拉，低有效；软件也配置上拉输入。
**一级和二级等效：任一触点低即按下，两个都高才完全松开。二级不自动表示快速。**
每组独立进行 10ms 按下/完全松开消抖；一级二级之间转换不产生假松开。
快速只叠加在方向上，单按快速不运动；升降同时按发送 STOP。
原始升降同时有效会立即保护为 STOP，不等待对向键消抖；冲突消失至少 10ms 且稳定状态不冲突后恢复。

## 5. 已统一的 A2 无线数据格式

固定空中 Payload 为 8 字节，CRC 不包括在这 8 字节里：

```text
ID_MSB ID ID ID_LSB  A2 COMMAND SEQ_H SEQ_L
```

| COMMAND（十六进制） | 意义 |
| --- | --- |
| 00 | STOP |
| 01 | UP |
| 02 | DOWN |
| 05 | UP_FAST |
| 06 | DOWN_FAST |

UP=01、DOWN=02、FAST=04，但 **04、03、07 和其他值均非法**。
示例：ID=1、快速上升、序号12：`00 00 00 01 A2 05 00 0C`。
序号是16位，本地 TX_DONE 后递增，65535 后回绕；不是可靠送达确认或防重放认证。
旧版 A1 只有通用 RUN/STOP，与当前 A2 不兼容。两端 `.h` 已定义相同常量。

**已实板确认过的 FIFO 行为必须保留：**

- TX FIFO 只写后 4 字节 DATA，Node ID 由硬件插入。
- RX FIFO 读取完整 8 字节，即 ID4＋DATA4。
- 曾错误地在 TX 写入8字节，造成接收数据一直是 ID=1、序号一直为1；已修复，不要改回对称读写。
- 固定包长度界面是8，寄存器 PAYLOAD_LENG 编码是7；Node ID模式1对应原寄存器0x47=0x0D。
- ID 寄存器0x48..0x4B按低字节在前配置，空中/日志按高字节在前显示。

发包及有效期：

- 按住有效方向：起始间隔随机40..60ms，持续发送完整当前状态。
- 方向/速度变化：优先终止旧状态发送，发送新状态。
- STOP：起始间隔25..35ms重复3包，然后不再持续发包；空闲无包正常。
- 221 最后一个有效控制包后 **85ms** 无更新即撤销无线命令。
- CRC、ID、A2标识、合法命令全部通过才刷新有效期；错误包不能续期。
- 不能把“没有空闲心跳”误判为故障，也不能把超时当成用户已经明确松键。

## 6. 221 完整控制板 GPIO 与不能混淆的事实

| GPIO | 功能 | 有效条件 |
| --- | --- | --- |
| PB3 | 共用上升方向回路检测 | 低 |
| PB4 | 共用下降方向回路检测 | 低 |
| PB5 | 有线快速请求检测 | 低 |
| PB12 | 无线上升请求 | 高 |
| PB13 | 无线下降请求 | 高 |
| PA9 | 上升继电器驱动 | 低 |
| PA8 | 下降继电器驱动 | 低 |
| PA10 | 快速继电器驱动 | 低 |
| PB6 | KM1运行许可 | 低 |
| PB11 | 公共软件禁止 | 高 |

关键硬件事实：

1. **PB3/PB4是经过硬件选择、限位等回路后的共用方向信号，不是独立有线按键，也不是电机实际动作反馈。**
2. `W_UP_RAW/W_DN_RAW/WIRED_IDLE/ESTOP_SENSE` 没有独立接入 MCU；不能虚构这些输入。
3. 硬件用 WIRED_IDLE 门控无线请求，具有有线优先关系，但 MCU 不能因此直接知道来源。
4. 实体急停纯硬件禁止操作回路，MCU不能独立识别具体急停状态。
5. PB11高使操作回路信号消失。不能保持PB11高，再等待PB3/PB4出现后才解除，否则可能死锁。
6. 普通松键/方向冲突用PB6停止许可并释放方向继电器，保持PB11放行以观察输入。
7. PB11高或PB6高不等于方向/快速继电器必然释放，它们有独立驱动路径，需要主动设置PA8/9/10。
8. 输出锁存器读回、方向信号、继电器实际触点和电机运行是不同层次，不能相互冒充。

接线文档第七节涉及 `Hardware/cmt2219b/cmt2219b_port.h`、PB14/PB13/PB15/PB12 的内容是**旧参考工程差异记录**。
当前实际 SPI 是 PA4/PA5/PA7/PB0，PB12/PB13保留给方向请求，不要按旧表改回。

## 8. 221 当前代码连接方式与执行时序

`ReceiverApp_Init`：先初始化安全执行GPIO/有线时基，再初始化无线，最后统一日志队列与配置维护回调。
`ReceiverApp_Process`：无线有效命令同步到共用执行适配，在无线处理前后都服务执行状态机。

- `wireless_demo.c` 现在是 RX-only A2 服务，负责收包、有效期、配对保存及USART1中断队列，不直接驱动执行器。
- `wired_control.c` 是原有纯C继电器状态机，最近接无线时该逻辑源文件未改。
- `wired_port.c` 管理公共执行GPIO、PB12/PB13请求、真实方向反馈和来源转换的释放等待。
- `WiredControl_SetRemoteCommand` 是共用执行入口，不要另写一套无线代码直接抢写PA8/9/10、PB6/PB11。
- 有无线意图时必须得到相应PB3/PB4方向信号，不能直接把无线命令合成反馈、绕过限位。
- 撤无线请求后等待释放稳定，避免残留RF反馈被误识别为有线再次启动。
- 无线故障/未配对不能持续禁止有线；无线初始化失败重试等执行空闲后进行，避免周期干扰正在运行的有线。
- SET/DEFAULT是显式维护：写Flash前暂时全局软件禁止，完成后解除，重新等待回路稳定。
- 输出锁存器读回不符会保持软件禁止，普通清除软件停止不能覆盖该故障，需要复位排查。

`wired_config.h` 当前参考参数：

| 参数 | 初值 |
| --- | --- |
| 启动安全保持 | 50ms |
| PB11放行后操作回路稳定 | 50ms |
| 输入有效确认 | 10ms；失效立即处理 |
| 撤PB6后保留原方向/速度驱动 | 50ms |

50/30/30ms来自旧程序参考，20ms也是初始参考值，**没有实测继电器触点和机械停机时间**。
此前100ms是响应目标，85ms是软件有效期阈值；不能声称所有换向、来源切换或机械停止均已保证100ms。

## 9. 尚未解决的核心问题：有线/无线混合操作

这是下一阶段重点，之前只允许暂缓，不代表问题不存在或已验收。

具体歧义示例：无线快速上升期间，有线按下慢速上升，PB3仍然为低；MCU无法仅凭PB3发现来源已切换。

当前适配器只是根据有效无线目标进入无线通路；无线结束后释放并返回有线采样。
**它不是完整优先级仲裁器。** 只考虑分别操作的测试路径；同时操作的速度选择、来源日志、接管与退出不能当作可靠结果。

后续设计需要处理并验证：

- 有线/无线同向不同速、反向、仅有线快速、双方同时释放或其中一方持续按住。

## 11. 日志如何判断

- `EVENT UP/UP_FAST/... PACKET`：无线命令通过校验，不等于执行器已经运行。
- `RX state=...`：无线解析层当前命令，不是电机运行状态。
- `you xian model up/down`：有线路径执行状态RUN、软件放行PB6。
- `wu xian model up/down`：无线路径执行状态RUN、软件放行PB6。
- `wait model`：回路稳定、准备、来源转换，或有无线意图但无匹配方向反馈。
- `sleep model`：执行空闲；`stop model`：停止释放、软件禁止或方向冲突等。
- `EVENT STOP TIMEOUT`：无线命令过期。硬件无急停输入，不应虚构准确的ESTOP事件。
- PB3/4/5打印真实采样；无线FAST不能伪装成PB5低。PB12/13仅是请求，受硬件门控。
- 211周期日志300ms，221状态/接收统计500ms，短暂过渡可能没有周期快照。
- err不是丢包数，LOGDROP/drop是日志丢弃，不是无线丢包；一行串口日志不等于一个无线包。
