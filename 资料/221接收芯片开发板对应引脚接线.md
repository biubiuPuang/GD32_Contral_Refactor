# 控制板 V1 GPIO 端口功能对照表

**主要依据：`SCH_控制板V1_2026-10-13.pdf` 的 3 页原理图。主控为 U7：GD32E230C8T6，48 脚封装。**

本版原理图中，U7 **共有 19 个 GPIO 接入了具体电路**，另外 20 个 GPIO 在图中未接线或标为不连接。实际使用的 19 个 GPIO 包含：10 个升降/快速/运行许可相关引脚，4 个无线芯片通信引脚，2 个调试串口引脚，2 个 SWD 引脚，以及 1 个指示灯引脚。

这份文件说明引脚和电路作用，供你完善现有程序使用。软件框架仍以你当前的框架为主，不把参考资料里的软件分层、状态机或恢复策略直接当成必须采用的方案。

## 一、先说明表格里的几个词

- **输入、输出**：都以 MCU 为参照。输入是 MCU 读取外部信号，输出是 MCU 向外部电路发出控制信号。
- **高、低电平**：指 MCU 管脚这一侧的逻辑电平。VCC 为板上 3.3V 逻辑电源，不是把 24V 直接接到 GPIO。
- **有线专用、无线专用、共用**：说明该接口服务于哪一部分功能，不代表 MCU 一定能从这个引脚识别请求来源。
- **低有效、高有效**：用于开关量信号。SPI、UART、SWD 的数据和时钟按通信时序工作，不能统一套用“高就有效、低就无效”。
- **图纸分析与实物状态分开**：下面的极性按元件正常、按图接线推导；没有把 GPIO 的输出值当成继电器实际触点位置或电机实际运行反馈。

图纸页码：第 1 页为 `POWER`，第 2 页为 `MAIN`，第 3 页为 `CONTROL`。

## 三、结合电路理解这些引脚

### 3.1 请求、方向反馈、继电器动作、电机运行是四件事

1. **提出无线请求**：MCU 用 PB12/PB13 提出上升或下降意图。
2. **得到有效方向信号**：请求通过有线优先门控、方向互锁、K1 选择和外部限位后，在 `LIFT1/LOWER1` 上形成方向信号，MCU 通过 PB3/PB4 检测。
3. **切换方向和速度接法**：PA8/PA9/PA10 控制 KA1/KA2/KA3 的线圈驱动。
4. **允许接通电机主电源**：PB6 允许 KM1 线圈驱动，同时还要有方向回路供电、操作回路许可及正确的执行条件。

因此，**PB12/PB13 提出请求，不等于方向已经通过硬件；PA8/PA9/PA10 使继电器吸合，也不等于电机已经通电运行。**

### 3.2 PB3/PB4 只能告诉你“最终方向信号”，不能直接告诉你“来源”

| PB3 | PB4 | MCU 可以据此判断什么 | 不能直接判断什么 |
| --- | --- | --- | --- |
| 低 | 高 | 检测到上升方向信号，未检测到下降方向信号 | 不能只凭这两个电平断言来源是有线 |
| 高 | 低 | 检测到下降方向信号，未检测到上升方向信号 | 不能只凭这两个电平断言来源是无线 |
| 高 | 高 | 当前两路方向有效信号均未检测到 | 不能直接认定按键都松开、急停已解除或机械已停止 |
| 低 | 低 | 同时检测到两路方向信号，需要按方向冲突处理 | 不能把它当成任意选择一个方向继续运行的依据 |

原理图没有把 `W_UP_RAW`、`W_DN_RAW` 和 `WIRED_IDLE` 接到 MCU。即使程序把 PB3/PB4 的采样结果存进名为 `wired` 的结构体，也不会因此变成“独立有线按键状态”。

### 3.3 PB6 与 PB11 的区别

以下按器件正常、按图接线说明，不代表实际触点状态已经被采集。

| 输出状态 | 操作回路和输入检测 | 对 KM1、电机的含义 |
| --- | --- | --- |
| **PB11 高**，PB6 任意 | 软件提出禁止，RLY3 被要求断开 `CTRL_SAFE`；正常情况下 PB3/PB4/PB5 的操作信号随之消失 | 正常电路下无法继续依靠该操作回路使 KM1 吸合；MCU 和无线芯片仍有自身供电 |
| **PB11 低、PB6 高** | 取消软件禁止；实体急停正常时，操作回路可供电，PB3/PB4/PB5 仍能检测操作信号 | KM1 线圈驱动被禁止；可以保持检测而不允许接通电机主电源 |
| **PB11 低、PB6 低**，但没有有效方向信号 | 操作回路可能已被允许，但方向回路没有给出有效方向 | PB6 低只是许可，不足以保证 KM1 吸合或电机运行 |
| **PB11 低、PB6 低**，存在有效方向信号且方向继电器、供电和限位条件均满足 | 操作回路和线圈驱动均被允许 | 具备接通 KM1、运行电机的相关条件；仍不能把 GPIO 电平当成触点实际闭合的测量结果 |

**PA8/PA9/PA10 对应继电器的线圈使用独立的 24V 驱动路径。PB6 高或 PB11 高，并不等于 KA1/KA2/KA3 一定释放。**

PB11 高导致操作信号消失时，不能据此判断“实体急停和全部升降按键都已经松开”。这是信号可观测性的限制，与你选择什么软件框架无关。

### 3.4 有线优先由哪些电路实现

- 有线原始上升、下降、快速信号分别经 U16、U17、U21 得到 `UPSIG`、`DNSIG`、`FASTSIG`；有输入时对应 SIG 为低。
- U23 生成 `WIRED_IDLE = UPSIG 与 DNSIG 与 FASTSIG`。三路有线信号都空闲时它才为高；任一路有线有效就使它为低。
- U20 用 `WIRED_IDLE` 对 PB12/PB13 的无线方向请求进行门控；有线有效时抑制无线方向请求。
- U24/U25/U26 对无线方向做交叉互斥；K1 参与有线/无线方向通路选择。

这说明“无线提出下降请求”和“无线下降请求真正通过硬件”是不同的。上述是稳态电路关系，不能由此直接得出继电器动态切换时间。

### 3.5 急停有关的极性链

按图中逻辑门连接，静态关系为：

```text
NK_PERMIT = MCUESTOP 或 ESTOP_SENSE
K_PERMIT  = 非 NK_PERMIT

PB11 = MCUESTOP
```

- 实体急停正常、U22 输入有电时，`ESTOP_SENSE` 被光耦拉低。
- 实体急停断开、U22 输入失电时，`ESTOP_SENSE` 被 R53 上拉为高。
- PB11 高或 `ESTOP_SENSE` 高，都会使 `K_PERMIT` 变低，撤销 Q8 对 RLY3 的线圈驱动。
- PB11 低，只是取消软件这一侧的禁止，**不能覆盖实体急停的禁止作用**。
- `ESTOP_SENSE` 未接到 MCU 输入脚，因此当前图纸没有独立的“MCU 读取实体急停状态”的 GPIO。

## 四、重要但没有直接接 MCU 的网络

这些名字出现在原理图中，但不是额外的 MCU GPIO，不能直接写成某个尚不存在的输入接口。

| 网络或器件 | 电路中的作用 | MCU 能否直接采到或直接控制 |
| --- | --- | --- |
| `W_UP_RAW` | 有线原始上升请求，来自 CN1 的 UP 端，经 U16 参与有线优先判断 | **没有独立 MCU 采样脚** |
| `W_DN_RAW` | 有线原始下降请求，来自 CN1 的 DO 端，经 U17 参与有线优先判断 | **没有独立 MCU 采样脚** |
| `W_FAST_RAW` | 有线原始快速请求；一支经 U21 参与硬件有线优先，另一支经 U6 给 PB5 检测 | **可以通过 PB5 间接检测**，不是 24V 原始网络直接连 MCU |
| `UPSIG/DNSIG/FASTSIG` | 有线原始信号经光耦转换后的逻辑量，送 U23 | 未直接接入 MCU；`FASTSIG` 与 PB5 的检测对象相同，但属于不同光耦支路 |
| `WIRED_IDLE` | 硬件产生的有线空闲标志，高表示三路有线输入均未检测到，低表示存在有线请求 | **未接 MCU**，不能假设软件已经拥有这个输入 |
| `ESTOP_SENSE` | U22 产生的实体急停相关检测信号，送 U15 | **未接 MCU**；PB11 是另一路软件禁止输出，不是该信号的输入脚 |
| `NK_PERMIT/K_PERMIT` | U15/U19 产生的禁止及反相许可信号 | 没有独立 MCU GPIO；由 PB11 与实体急停链共同影响 |
| `DRV_UP/DRV_DN` | 硬件门控后的无线驱动信号，经 Q6/Q7 驱动 RLY1/RLY2 | 没有独立 MCU GPIO；不是 PA9/PA8 的别名 |
| `RF_UPOUT/RF_DNOUT` | RLY1/RLY2 将 `CTRL_SAFE` 接向无线方向通路后的输出 | 没有独立 MCU GPIO，也不是 PB12/PB13 的同电压直连网络 |
| `CTRL_SAFE` | RLY3 控制的操作回路供电 | **不是 MCU 的 VCC**；PB11 通过逻辑电路间接控制其许可 |
| K1 | 由 `RF_UPWANT/RF_DNWANT` 经二极管及 Q5 驱动，参与有线/无线方向选择 | 没有独立的“切换 K1”GPIO，也没有接到 MCU 的 K1 触点反馈 |
| KM1 实际触点状态 | 决定电机主电源是否真正接通 | 图中没有独立触点状态反馈输入；PB6 只是线圈驱动许可 |

## 七、原理图与当前工程接收驱动的脚位差异

以下只读核对现有 `Hardware/cmt2219b/cmt2219b_port.h`，用来指出代码与图纸的差异。**GPIO 用途以本次提供的原理图为准。**

| 接口 | 当前工程接收驱动的定义 | 本次原理图的连接 | 说明 |
| --- | --- | --- | --- |
| CMT2219B CSB | PB14 | **PA4** | 原理图为 U7 的 14 脚接 `SPI_CSB` |
| CMT2219B SCLK | PB13 | **PA5** | 原理图 PB13 已用于无线下降请求，不能同时作为该通信时钟 |

参考框架文件把无线接口概括写为“PA4/PA5/PA6/PA7 等”；实际图纸连接明确为 **PA4、PA5、PA7、PB0**，PA6 未连接，因此本表采用原理图的逐脚结果。

## 八、用于编写你现有框架时的直接含义

- **采集输入**：PB3/PB4 保存为共用方向反馈；PB5 保存为有线快速检测。不要仅因结构体名字叫 `wired` 就把所有反馈认定为有线来源。
- **无线请求**：无线协议解析得到的上升、下降意图，经过你框架中的判断后，使用 PB12/PB13 提出请求。
- **继电器执行**：PA8/PA9/PA10 控制方向与速度接法，PB6 控制 KM1 线圈驱动许可，PB11 控制公共软件禁止。
- **不能虚构的输入**：本版图纸没有独立接入 MCU 的有线上升 RAW、有线下降 RAW、WIRED_IDLE、实体急停检测、K1/KM1 触点反馈。
- **无线快速**：没有单独的无线快速请求 GPIO。PA10 是共用执行输出，PB5 只反映有线快速；无线快速与有线方向的来源仲裁条件需要另外明确，不能由 PB5 单独代表全部有线状态。
- **输出初始化目标**：PB11 高、PB6 高、PB12/PB13 低、PA8/PA9/PA10 高。实现 GPIO 初始化时，先开启对应时钟，先写默认电平再切换输出模式；通信接口优先使用现有 BSP 或官方库封装，并按实际脚位核对配置。

这些是接口事实和使用说明，不替换你当前 `main()` 的软件组织方式，也不在本文件中确定模式切换等待时间或急停解除策略。
